# ATURAN KERJA GITHUB
## KELOMPOK 4

### 1. Penggunaan Branch

Setiap anggota wajib membuat branch sendiri untuk mengerjakan tugas agar perubahan tidak langsung masuk ke branch utama (`main`).

Contoh nama branch:
- `feat/backend-login`
- `feat/frontend-web`
- `feat/mobile`
- `docs/dokumentasi`

### 2. Aturan Commit

Setiap perubahan wajib disimpan menggunakan commit dengan format:

`<tipe>(<bagian>): <ringkasan perubahan>`

Contoh:
- `feat(backend): tambah fitur login`
- `fix(backend): perbaiki validasi login`
- `docs(kelompok-01): perbarui dokumentasi`
- `test(frontend-web): tambah bukti pengujian`

Jenis commit:
- `feat`: fitur atau tugas baru.
- `fix`: perbaikan kesalahan.
- `docs`: perubahan dokumentasi.
- `test`: pengujian sistem.

### 3. Push Perubahan

Setiap anggota wajib melakukan push setelah melakukan commit agar hasil pekerjaannya tersimpan di repository GitHub.

### 4. Pull Request

Setiap pekerjaan yang sudah selesai wajib diajukan melalui Pull Request (PR) untuk meminta penggabungan ke branch utama.

Pull Request harus menyertakan:
- Ringkasan perubahan.
- Bukti hasil pekerjaan.
- Informasi tugas yang dikerjakan.

### 5. Review dan Merge

Setiap Pull Request harus diperiksa oleh anggota lain sebelum digabungkan ke branch `main`.

Anggota yang melakukan review dapat memberikan saran atau meminta perbaikan jika ditemukan kesalahan.

### 6. GitHub Issue

Setiap kendala selama pengerjaan wajib dicatat melalui GitHub Issue dengan mencantumkan:
- Masalah yang terjadi.
- Langkah untuk mengulangi masalah.
- Bukti kendala.
- Upaya perbaikan yang sudah dilakukan.

Jika masalah sudah diselesaikan, tautkan commit atau Pull Request penyelesaiannya sebelum menutup Issue.

### 7. Keamanan Repository

Seluruh anggota dilarang mengunggah:
- Password.
- Token akses.
- File `.env` asli.
- Folder dependensi.

### 8. Kesepakatan Kelompok

Seluruh anggota Kelompok 4 wajib mengikuti aturan kerja GitHub agar proses pengembangan proyek Sistem Informasi Mikrokredensial berjalan teratur dan dapat dikerjakan bersama.
